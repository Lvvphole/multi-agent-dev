# Memory Authority

Load this file for context selection, retrieval, durable memory, provenance, inheritance, correction, or freshness.

## Context classes

- Layer 3 reference context is stable, governed material that constrains repeated work.
- Layer 4 working context is run-specific input, intermediate output, evidence, or result.
- Keep the classes separate. Persistence does not convert working content into a rule.

## Required controls

- `MEMORY != AUTHORITY` and `MEMORY != CANONICAL STATE`.
- Every durable record identifies source, provenance, scope, creation time, applicable state revision, evidence class or confidence, freshness or expiry, and correction path.
- Retrieval follows lineage screen, admission, freshness check, then role-, goal-, and information-rights projection.
- Load only context named by the selected route or stage Inputs table.
- Never give a child unrestricted parent memory, full conversation history, mutable context, permissions, or approval rights.
- A memory candidate becomes durable only through the configured admission policy.
- Repeated corrections may propose a source or policy change; they cannot silently rewrite governance.

## ICM use

ICM is the repository-development context method: root identity, explicit routing, stage contracts, stable references, and inspectable run artifacts. Runtime agent memory remains governed by the memory harness, not by filesystem convention alone.
